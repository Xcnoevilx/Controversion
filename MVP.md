# Controversion MVP

## Goal

The first version of Controversion should prove one core idea:

Can controversial subjects be presented in a structured way that lets people examine claims, evidence, counterevidence, sources, and alternative explanations for themselves?

The MVP should focus on doing this well before adding complex community or automation features.

---

# 1. Home Page

The home page should provide:

- Controversion introduction
- Featured topics
- Popular topics
- Recently added topics
- Category browsing
- Search

---

# 2. Topic Page

Every controversy gets its own topic page.

Display:

- Topic title
- Neutral summary
- Category
- Tags
- Current status
- Major claims
- Alternative explanations
- Sources
- Open questions
- Last updated date

---

# 3. Claims

Each topic may contain multiple specific claims.

Each claim displays:

- Claim statement
- Description
- Evidence supporting it
- Evidence challenging it
- Confidence assessment
- Explanation of the assessment

Users should be able to examine the evidence rather than simply seeing a verdict.

---

# 4. Evidence Cards

Each piece of evidence should display:

- Evidence title
- Short description
- Supports / Challenges / Neutral / Unclear
- Evidence strength
- Source
- Reasoning
- Link to source

Evidence cards should make opposing evidence easy to compare.

---

# 5. Source Pages

Each source should have information including:

- Title
- Author
- Publisher
- Source type
- Publication date
- Original URL
- Archived URL when available
- Credibility information
- Evidence connected to the source

---

# 6. Search

Users should be able to search:

- Topics
- Claims
- Categories
- Tags

Advanced search can come later.

---

# 7. Categories

Initial categories:

- Science
- History
- Politics
- Technology
- Health
- Religion
- Paranormal
- Current Events
- Media
- Other

---

# 8. Initial Content

The MVP should launch with a small collection of well-developed topics rather than hundreds of incomplete ones.

Target:

10–20 complete topics.

Topics should include a mixture of:

- Historical controversies
- Scientific disputes
- Modern conspiracy theories
- Technology controversies
- Current misinformation examples

Each initial topic should demonstrate how the Controversion evidence system works.

---

# 9. Administration

The first version needs a simple way for administrators to:

- Create topics
- Edit topics
- Add claims
- Add evidence
- Add sources
- Add alternative explanations
- Change assessments
- Correct mistakes

A sophisticated administration dashboard is not required initially.

---

# 10. Not Required for MVP

These features should wait until the core platform works:

- Public user accounts
- Comments
- Community ratings
- User submissions
- Reputation system
- Automated research bot
- AI-generated assessments
- Mobile application
- Notifications
- Complex recommendation algorithms
- Monetization

---

# 11. Technical MVP

The initial application needs:

Frontend
→ Topic browsing and evidence presentation

Backend
→ Application API and content management

Database
→ Topics, claims, evidence, sources and relationships

Search
→ Basic topic and claim search

Deployment
→ Public web server with HTTPS

Version Control
→ GitHub

---

# 12. Success Criteria

The MVP is successful when a visitor can:

1. Find an interesting controversy.
2. Understand the central question.
3. Identify the major competing claims.
4. Examine evidence supporting and challenging those claims.
5. inspect the original sources.
6. Understand why evidence received its assessment.
7. See unanswered questions.
8. Reach their own conclusion.

---

# Core MVP Rule

Do not build everything at once.

Build the investigation experience first.

Everything else can grow around it.
